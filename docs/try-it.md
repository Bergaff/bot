# Как попробовать: расширение в своём браузере за 5 минут

Расширение уже собрано — папка [`extension/`](../extension/) (Chrome MV3) и один файл
[`userscript/poputchka-collector.user.js`](../userscript/) для Tampermonkey. Оно **только
читает** открытую вкладку Telegram Web: находит объявления о передаче посылок, отсеивает
болтовню и пассажирские попутки и отправляет их на сервер (`POST /api/ingest`). Ничего не
публикует, не отправляет и не ставит реакции от вашего имени.

---

## Что уже проверено, а что нужно проверить вживую

| Часть | Состояние |
|---|---|
| Разбор текста объявления (города, дата, вес, цена, контакты) — `src/parser.ts` | ✅ тот же код, что в проде `parcel`; покрыт тестами |
| Серверный сбор публичных чатов `t.me/s/<username>` | ✅ работает на фикстурах реальной разметки и на живом `t.me/s/durov` |
| Приём сообщений `POST /api/ingest`, дедупликация, квоты, ошибки | ✅ 359 тестов + сквозные прогоны |
| Чтение DOM Telegram Web (`extension/dom.cjs`) | ⚠️ написано по актуальной разметке и покрыто 33 тестами на мини-DOM, но **в живом Telegram Web его нужно проверить один раз** — для этого есть кнопка «Диагностика вкладки» (ниже). Telegram иногда меняет классы, поэтому селекторов несколько и есть запасные стратегии |

То есть: «определение сообщений» рабочее, а единственная неизвестная — конкретные селекторы
в живом Telegram Web. Проверяется за минуту и без отправки данных (шаг 5).

## Шаг 1. Взять код

Любым способом:

- **ZIP**: <https://github.com/Bergaff/bot> → ветка `arena/01a0a64d-bot` → `Code` →
  `Download ZIP` → распаковать. Нужны только папки `extension/` (или файл из `userscript/`)
  и, для локального сервера, весь репозиторий.
- **git**: `git clone -b arena/01a0a64d-bot https://github.com/Bergaff/bot`

## Шаг 2. Поставить расширение в браузер

Chrome / Edge / Brave / Яндекс.Браузер:

1. открыть `chrome://extensions`;
2. включить **«Режим разработчика»** (справа сверху);
3. **«Загрузить распакованное расширение»** → выбрать папку `extension/`;
4. появится иконка «попутка. — сбор объявлений из чатов» (закрепите её на панель).

Альтернатива — Tampermonkey: установить `userscript/poputchka-collector.user.js`.
У юзерскрипта нет попапа (настройки правятся в `localStorage`, инструкция в шапке файла),
и он работает в контексте страницы, поэтому **локальный `http://127.0.0.1` из https-страницы
не достанет** — нужен https-адрес сервера. Для первой проверки лучше расширение.

## Шаг 3. Поднять сервер, куда отправлять

### Вариант A — локально у себя (рекомендуется)

Двойной клик по **`start-local.bat`** (Windows) или в терминале **`./start-local.sh`**
(macOS/Linux). Скрипт проверит Node.js (нужен ≥ 22.18), один раз поставит зависимости и
поднимет сервер, а в консоль напечатает значения для попапа:

```
serverUrl :  http://127.0.0.1:8790
token     :  demo-ingest-token
админка   :  http://localhost:8790     (ключ админа demo-admin-token панель подставит сама)
```

Это тот же сервер, что стоит в демо: настоящая админ-панель, настоящий API и локальная база
(sqlite вместо D1) — собранные заявки сразу видно глазами. Остановить: `Ctrl+C`.

Вручную, без скрипта: `npm install && node parcel/demo/server.mjs`.

### Вариант B — вообще без установки

Если сервер запущен в песочнице Arena (панель предпросмотра «Демо админки»), возьмите её
https-адрес вида `https://8790-<id>.e2b.app` и вставьте в `serverUrl`, токен тот же —
`demo-ingest-token`. Адрес живёт, пока жив сеанс, зато ничего ставить не нужно, и
https-адрес не спотыкается о mixed content.

### Вариант C — боевой сервер

После переноса в `parcel` (`INTEGRATION.md`): `serverUrl = https://<ваш-домен>`,
`token = INGEST_TOKEN` (`wrangler secret put INGEST_TOKEN`).

## Шаг 4. Заполнить попап

Клик по иконке расширения:

| Поле | Что вписать |
|---|---|
| `serverUrl` | `http://127.0.0.1:8790` (вариант A) или https-адрес (B/C) |
| `token` | `demo-ingest-token` (A/B) или ваш `INGEST_TOKEN` (C) |
| Белый список | 1–2 чата, построчно: название чата, `@username` или ссылку `t.me/<username>`. **Пусто — не читается ничего**, так задумано |
| Интервал опроса | 120–180 с (минимум 60) |
| Подтверждение перед отправкой | оставьте включённым на первое время |

Нажать **«Сохранить»**, затем **«Проверить сервер»** — должно написать, что сервер отвечает
и сколько сообщений принято сегодня.

## Шаг 5. Проверить определение сообщений (без отправки)

1. Открыть <https://web.telegram.org> и войти в аккаунт.
2. Перейти в чат из белого списка.
3. Клик по иконке расширения → **«Диагностика вкладки»**.

Ничего не отправляется: расширение показывает, сколько сообщений оно видит в DOM, какой
стратегией селекторов удалось их прочитать, сколько распознано как объявления и сколько
отсеяно (болтовня, пассажирские, старые). Если вместо этого «не могу прочитать сообщения» —
Telegram показывает другую разметку: что делать, написано в
[`extension/README.md`](../extension/README.md), раздел про починку селекторов.

## Шаг 6. Отправить и посмотреть заявки

- **«Отправить найденные»** — один проход руками (в режиме подтверждения спросит «да/нет»);
- дальше расширение делает проход само, раз в `intervalSec`;
- счётчики в попапе: найдено / отправлено / создано заявок / дубликаты / пропущено;
- **«Пауза»** — остановить мгновенно, **«Сбросить счётчики»** — обнулить статистику;
- заявки появляются в админке: <http://localhost:8790> → вкладка **«очередь»** → карточка с
  бейджем **«расширение»**; у приватного чата ссылки на исходное сообщение не будет
  (её просто не существует), у публичного — будет.

Повторная отправка тех же сообщений даёт `дубликаты` — их режет локальный лог
`chatId:messageId` в браузере и `tg_seen` + сравнение по смыслу на сервере.

## Если что-то не так

| Симптом | Причина | Что делать |
|---|---|---|
| «Активная вкладка — не Telegram Web» | попап открыт не на `web.telegram.org` | перейти на <https://web.telegram.org> |
| «Вкладка не отвечает» | страница загружена до установки расширения | обновить `web.telegram.org` |
| «Не достучались до сервера» | сервер не запущен / другой порт / mixed content | проверить, что `start-local` работает; для https-страницы использовать https-адрес или `http://127.0.0.1` (localhost браузером разрешён) |
| URL не сохраняется: «должен начинаться с https://» | ввели обычный http-адрес (не локальный) | годятся `https://…` и `http://127.0.0.1:8790` / `http://localhost:8790` |
| `401` | неверный `token` | для локального сервера — `demo-ingest-token` |
| `503` | на сервере не задан `INGEST_TOKEN` | `wrangler secret put INGEST_TOKEN` (прод) |
| `429` | больше 60 запросов в час | расширение само ждёт `Retry-After`; увеличьте интервал опроса |
| «не могу прочитать сообщения» | Telegram поменял разметку | `extension/README.md` → починка селекторов; данные при этом не теряются и не отправляются |
| Ничего не находится, ошибок нет | чат не в белом списке | добавить чат в белый список и сохранить |
| Заявок нет, а «найдено» растёт | всё отсеяно как болтовня/пассажирские | так и должно быть в обычных чатах; проверьте на чате с объявлениями о посылках |

## Проверить определение сообщений без браузера

```bash
npm install
npm run scan -- durov          # прочитать t.me/s/durov и показать, что разобрал парсер
npm run scan -- drivers_pl_by --limit 5
node parcel/demo/server.mjs    # админка + «запустить сбор сейчас» (зеркало фикстур, без интернета)
npm test                       # 359 тестов: парсер, DOM-чтение, оркестратор, сервер, UI
```

[`extension/README.md`](../extension/README.md). Порядок ввода в работу на проде —
[`docs/rollout.md`](rollout.md).
