# Демо админ-панели (этап 6)

Один процесс, в котором можно **пощупать блок авто-сбора до правки прод-файла** `public/app.js`
в `Bergaff/parcel`: настоящая разметка админки, настоящий API из `src/server.ts`, настоящая
база (sqlite вместо D1/KV) и веб-превью `t.me/s/`: если `t.me` доступен, сборщик ходит на
настоящий Telegram (добавлять можно любые публичные чаты), иначе включается зеркало на
фикстурах — то есть демо работает и без интернета.

Зачем:

- проверить четыре правки `app.js` глазами, а не только тестами;
- показать заказчику, как будет выглядеть вкладка «чаты» и очередь модерации с бейджами
  «сборщик» / «расширение»;
- отрепетировать сценарии обкатки (сломанный чат, дубли, авто-отключение, квота ИИ) —
  см. [`docs/rollout.md`](../../docs/rollout.md), раздел «День 0».

---

## Запуск

```bash
npm install                        # один раз
node parcel/demo/server.mjs        # http://localhost:8790
node parcel/demo/server.mjs 9000   # свой порт
```

Сервер печатает всё, что нужно:

```
демо админки (этап 6): http://0.0.0.0:8790/
  ADMIN_API_TOKEN=demo-admin-token  INGEST_TOKEN=demo-ingest-token
  источник превью t.me/s: https://t.me/s  (настоящий t.me)
    добавлять можно любые публичные чаты/каналы с открытой историей
  настоящий API: /api/admin/watch-chats, /api/admin/collect, /api/admin/collect/status, /api/ingest
```

Без интернета вместо двух средних строк будет:

```
  источник превью t.me/s: http://127.0.0.1:8790/mirror/s  (зеркало на фикстурах, t.me недоступен)
    зеркало знает только чаты из фикстур: durov, drivers_pl_by, posylki_pl_by, off_chat
    остальные юзернеймы дадут «нет веб-превью» — это не баг, а отсутствие интернета
```

База создаётся при первом запуске: `.data/demo.db` в корне репозитория. Ключ админа
подставляется сам (`demo-admin-token`), входить не нужно.

Кнопка **«сбросить демо-данные»** в полосе вкладок (или `POST /api/admin/demo/reset`)
очищает заявки и лог `tg_seen`, обнуляет курсоры, ошибки и счётчики чатов и засеивает данные
заново. Удалить файл базы — то же самое, но с нуля. Рядом — **«запустить сбор сейчас»**
(прогон всех чатов с `toast()`-итогом) и **«обновить»** (перечитать список).

## Что внутри

| Часть | Откуда | Комментарий |
|---|---|---|
| `/demo-bundle.js` | склейка `helpers.js` + `../app-auto-collect.js` + `demo.js` | «`app.js` в миниатюре»: собирается на каждый запрос, поэтому правки в `app-auto-collect.js` видны после F5 |
| `helpers.js` | настоящие помощники из `public/app.js` parcel | `el()`, `$()`, `toast()`, `adminApi()`, `sourceContent()`, `contactInfo()`, `fmtDate()`, `sourceLinkUrl()` — **уже с Правкой 4** |
| `../app-auto-collect.js` | тот самый блок, который вставляется в `public/app.js` | таблица обхода, действия, форма добавления, отчёт прогона, `originBadge()`, фильтр очереди |
| `demo.js` | демо-обвязка | копии `loadAdmin()` и `renderAdminChats()` из `app.js` — **уже с Правками 1–3**, переключение вкладок, сброс демо |
| `/api/*` (кроме заглушек) | `src/server.ts` → `app.fetch(request, env)` | настоящий код воркера: `watch-chats`, `collect`, `collect/status`, `ingest`, CORS, rate limit |
| база и KV | `local/sqlite-env.ts` (`node:sqlite`) | D1 и KV заменены одним файлом; код из `src/` разницы не замечает |
| `/mirror/s/<username>` | `local/mock-tme.mjs` + `tests/fixtures/` | веб-превью без интернета: `COLLECT_PREVIEW_BASE` переключает сборщик на зеркало (по умолчанию сервер сам выбирает — настоящий `t.me`, если он отвечает) |
| демо-заглушки | `server.mjs` → `src/store.ts` | `/api/admin/listings`, `/source-chats`, `/chat-links`, `/ensure-chat-links`, `/demo/reset`: в `parcel` эти ручки уже есть, в этом standalone-репозитории — нет |

Окружение демо (задаётся в `server.mjs`):

```js
ADMIN_API_TOKEN: 'demo-admin-token', INGEST_TOKEN: 'demo-ingest-token',
COLLECT_ENABLED: '1', COLLECT_MAX_CHATS: '10', COLLECT_MAX_PAGES: '2',
COLLECT_MAX_AGE_DAYS: '200',        // фикстуры датированы прошлыми месяцами
COLLECT_AI_DAILY_LIMIT: '20',       // AI_API_KEY не задан → ИИ не вызывается вовсе
// COLLECT_PREVIEW_BASE выбирается при старте: https://t.me/s, если t.me отвечает,
// иначе http://127.0.0.1:8790/mirror/s. Переопределяется переменной окружения
// COLLECT_PREVIEW_BASE, зеркало принудительно — DEMO_OFFLINE=1.
```

## Демо-данные

Чаты в обходе:

| username | тип | что показывает |
|---|---|---|
| `durov` | канал | живой канал, но без объявлений → всё уходит в `skipped`; `?before=` листается на вторую фикстуру |
| `drivers_pl_by` | супергруппа | объявления находятся → заявки с `origin='collector'` и ссылкой `t.me/drivers_pl_by/<id>` |
| `broken_channel` | канал | страница отдаётся, но разметка чужая → `markup_changed`, три попытки, авто-отключение и алерт |

Заявки в очереди: пять штук трёх источников (`bot`, `collector`, `extension`), одна из них
`published` — чтобы было что показать на вкладке «доска». Для одного приватного чата задана
ссылка через `chat_links` (`-1001234567890` → `t.me/drivers_pl_by`) — подпись источника
становится кликабельной.

Зеркало знает четыре имени: `durov`, `drivers_pl_by`, `gone_channel` (404 + страница
«чат не найден»), `broken_channel` (200 с чужой разметкой). Любой другой username → 404,
поэтому на нём удобно проверять обработку несуществующего чата.

## Что попробовать

1. **Вкладка «чаты»** — таблица обхода: username, тип, вкл/выкл, курсор, последняя проверка,
   найдено/создано/отсеяно, последняя ошибка; ниже — «Отчёт последнего прогона и статус
   источников» (`GET /api/admin/collect/status`).
2. **«Проверить сейчас»** на `drivers_pl_by` → прогон одного чата, отчёт, заявки в очереди
   с бейджем «сборщик» и ссылкой на исходное сообщение.
3. **«Запустить сбор сейчас»** → прогон всех чатов; сравнить `totals` с таблицей.
4. **Повторный прогон** того же чата → `created = 0`, `duplicate = N`: дедупликация `tg_seen`.
5. **Сломанный чат**: «проверить сейчас» на `broken_channel` три раза подряд → ошибка
   `markup_changed`, счётчик ошибок, авто-отключение и алерт админам. «Включить» +
   «сбросить курсор» возвращают чат в обход.
6. **Добавить чат**: `gone_channel` → 404; `durov` → живой, но объявления не находятся;
   `@bad name` → ошибка валидации (поле подсвечивается, `toast()`).
7. **Фильтр очереди по источнику** (вкладка «очередь», после сброса демо — 4 заявки):
   «все · 4», «бот · 2», «сборщик · 1», «расширение · 1». Счётчики считаются по загруженному
   списку, `#admin-count` остаётся про всю очередь; опубликованная заявка видна на вкладке «доска».
8. **Расширение без браузера** — тот же контракт `POST /api/ingest`:

```bash
curl -s -X POST http://localhost:8790/api/ingest \
  -H "Authorization: Bearer demo-ingest-token" -H 'Content-Type: application/json' \
  -d '{"collector":"tg-web-ext/1.0.0","messages":[{
        "chatId":"ext:-100777","chatTitle":"Попутки Минск","messageId":9001,
        "date":"2026-09-15T18:00:00Z","text":"Еду Минск → Гродно 20.09, возьму посылку до 10 кг, 25 BYN, @ivan_m",
        "author":"Иван"}]}' | jq .summary
# → {"received":1,"created":1,"duplicate":0,"skipped":0,"invalid":0}
```

Заявка появится в очереди с бейджем «расширение» и **без** ссылки на источник (приватный чат).

9. **Дедупликация по смыслу** (`src/dedupe.ts`, копия из parcel): одно и то же объявление
   двумя разными сообщениями — вторая заявка не создаётся, существующая освежается:

```bash
curl -s -X POST http://localhost:8790/api/ingest \
  -H "Authorization: Bearer demo-ingest-token" -H 'Content-Type: application/json' \
  -d '{"collector":"manual-check","messages":[
        {"chatId":"web:drivers_pl_by","messageId":910001,"text":"20.09 Варшава — Минск, возьму посылку до 20 кг, +48 579 264 254"},
        {"chatId":"web:drivers_pl_by","messageId":910002,"text":"20.09 Варшава — Минск, возьму посылку до 20 кг, +48 579 264 254"}]}' \
  | jq '.summary, [.results[] | {messageId, status, duplicateWhy}]'
# summary: created 1, duplicate 1
# 910002 → duplicate, «тот же человек (+48 579 264 254), тот же маршрут Варшава → Минск, дата та же (2026-09-20)»
```

10. **Сводка мониторинга** (этап 7) против демо:

```bash
node scripts/collect-report.mjs --url http://localhost:8790 --token demo-admin-token
```

## Как это связано с продом

- Блок `parcel/app-auto-collect.js` **переносится в `parcel/public/app.js` дословно**
  (вставляется в конец файла: `app.js` загружается как `type="module"`, отдельным
  `<script>` его не подключить). Четыре точечные правки вокруг него — в
  [`INTEGRATION.md`](../../INTEGRATION.md), раздел 4.
- Та же склейка (помощники + блок) прогоняется в мини-DOM тестами
  [`tests/admin-ui.test.ts`](../../tests/admin-ui.test.ts), поэтому демо и тесты не разъедутся.
- В `parcel` папка `demo/` **не переносится** — это стенд, а не часть продукта.
