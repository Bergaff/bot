# Клиентская часть: расширение и юзерскрипт для Telegram Web

Этап 3 ТЗ (`parcel/docs/tz-auto-collection.md`, вариант B). Работает в **уже открытой
вкладке** `web.telegram.org` на аккаунте заказчика и **только читает DOM**: никаких
кликов, отправки сообщений, реакций и пересылок. Найденные объявления уходят на сервер
в `POST /api/ingest` и там попадают в очередь модерации (`status = pending`).

Две одинаковые по поведению поставки из одних и тех же файлов:

| Что | Куда ставить | Файлы |
|---|---|---|
| Расширение Chrome (MV3) | `chrome://extensions` → «Загрузить распакованное расширение» → папка `extension/` | `manifest.json`, `popup.html`, `popup.js`, `content.js`, `core.cjs`, `dom.cjs`, `vendor/parser.js` |
| Юзерскрипт (Tampermonkey/Violentmonkey) | открыть `userscript/poputchka-collector.user.js` → «Установить» | один файл, собирается из тех же исходников |

## Что делает проход

```
таймер (60–600 с, по умолчанию 120)
  → какой чат открыт? (dom.readChatInfo: заголовок, @username из хэша, peer-id из URL)
  → чат в белом списке?  нет → сообщения НЕ ЧИТАЮТСЯ вовсе
  → чтение последних N сообщений ленты (dom.harvest, N = maxPerChat, по умолчанию 30)
  → клиентский детект на бандле src/parser.ts: пассажирские, болтовня, сервисные — в корзину
  → не старше maxAgeHours (72) и ещё не отправлялось (локальный лог chatId:messageId)
  → confirmMode? да → список в панели, ждём клик «Отправить найденные»
  → батчи по batchSize (≤ 20) → POST /api/ingest, Authorization: Bearer <INGEST_TOKEN>
  → счётчики (найдено/отправлено/создано/дубли/отсеяно) + лог отправленного в storage
```

Панель с состоянием, кнопками «Отправить найденные», «Пауза», «Диагностика» и
«Настройки» — в правом нижнем углу вкладки.

## Установка расширения

Пошагово «с нуля до первой заявки», включая локальный сервер одним кликом
(`start-local.bat` / `./start-local.sh`) — в [`docs/try-it.md`](../docs/try-it.md).

1. Соберите бандл парсера (нужен один раз, файл `vendor/parser.js` уже лежит в репозитории):
   ```bash
   npm install
   npm run build:ext
   ```
2. `chrome://extensions` → включите «Режим разработчика» → «Загрузить распакованное
   расширение» → выберите папку `extension/`.
3. Откройте `https://web.telegram.org/k/` (или `/a/`), войдите в аккаунт заказчика и
   зайдите в чат из белого списка.
4. Кликните иконку расширения и заполните настройки (см. ниже) → «Сохранить».

## Установка юзерскрипта

1. `npm run build:ext` → `userscript/poputchka-collector.user.js`.
2. В Tampermonkey/Violentmonkey: «Создать новый скрипт» → вставить содержимое файла
   (или открыть файл в браузере — менеджер предложит установку).
3. Настройки юзерскрипта живут в `localStorage["poputchka"]` (попапа у него нет).
   В консоли вкладки Telegram Web:
   ```js
   localStorage.setItem('poputchka', JSON.stringify({ settings: {
     serverUrl: 'https://pop-utka.app',
     token: 'ВАШ_INGEST_TOKEN',
     // '::' — один рум (топик) форум-чата, названием или id; без '::' читаются все румы
     whitelist: ['Водители Польша–Беларусь', 't.me/drivers_pl_by', 'Граница :: Очередь BY-PL'],
     intervalSec: 120, batchSize: 20, maxPerChat: 30,
     confirmMode: true, paused: false, maxAgeHours: 72, requireContact: false,
   }}));
   location.reload();
   ```

## Настройки

| Поле | По умолчанию | Смысл |
|---|---|---|
| `serverUrl` | — | базовый URL сервера, например `https://pop-utka.app` (без `/api`). Для локальной отладки годится `http://127.0.0.1:8790` или `http://localhost:8790` — прочие `http://` адреса попап не примет: страница Telegram Web открыта по https, и браузер заблокирует запрос как mixed content |
| `token` | — | `INGEST_TOKEN` с сервера: `wrangler secret put INGEST_TOKEN` |
| `whitelist` | `[]` | чаты, которые вообще разрешено читать: названия или `t.me/…`. Запись с `::` ограничивает один рум (топик) форум-чата: `Граница :: Очередь BY-PL` или `Граница :: 7`. Без `::` читаются все румы чата. **Пусто — ничего не читается** |
| `intervalSec` | `120` | период опроса, жёстко ограничен 60–600 с |
| `batchSize` | `20` | сообщений в одном `POST` (серверный предел — 100) |
| `maxPerChat` | `30` | сколько последних сообщений ленты читать за проход |
| `maxAgeHours` | `72` | старее — не отправляем (сервер дополнительно режет по `INGEST_MAX_AGE_DAYS`) |
| `confirmMode` | `true` | спрашивать подтверждение перед отправкой |
| `requireContact` | `false` | слать только сообщения с телефоном или `@username` |
| `paused` | `false` | пауза: ничего не читать и не отправлять |

Токен хранится только в `chrome.storage.local` / `localStorage` этого браузера и в
репозиторий не попадает.

## Панель как пульт: «аккаунт Telegram», румы, журнал

Авторизация Telegram остаётся здесь, в браузере: расширение читает DOM открытой вкладки,
никакого логина по номеру телефона на сервере нет (юзербот — это риск бана аккаунта и
прямой запрет ТЗ п. 1.3). Панель сервера при этом работает пультом этого единственного
авторизованного аккаунта.

Что происходит между ними:

| Кто | Что | Как |
|---|---|---|
| расширение → панель | «аккаунт подключён»: текущий чат и рум, счётчики, состояние, ошибки | `POST /api/extension/heartbeat` каждый проход (и в ответе сразу приходят настройки) |
| панель → расширение | белый список чатов и румов, интервал опроса, пауза | `GET /api/extension/config` в начале каждого прохода |
| модератор в панели | журнал принятого: чем стало сообщение и **ссылка на него** | `GET /api/admin/ingest/log` |

Практические следствия:

- Настройки из попапа остаются запасными: как только панель задала белый список, он
  **перекрывает** локальный (в попапе это видно строкой «настройки из панели»).
- Чтобы забрать настройки немедленно, а не в следующий проход: попап → «Настройки из панели».
- Ссылки в журнале: публичный чат — `t.me/<username>/<id>`, приватная супергруппа —
  служебная `t.me/c/<id>/<msg>` (открывается у участников чата). Её и пересылают вручную:
  расширение ничего не публикует и не пересылает от вашего имени.
- Если в адресе вкладки peer-id нет (например, личный чат без `p=`/`#-100…`), ссылки на
  сообщение не существует — журнал честно пишет «ссылки нет», а не подсовывает битую.
- Вкладка закрыта или браузер выключен — через ~12 минут панель покажет «нет связи».
  Это нормально: сбор продолжится, когда вкладку снова откроют.

## Если попап не видит вкладку: «Подключить к вкладке»

Chrome внедряет контент-скрипт при загрузке страницы. Внедрения не будет, если вкладка
открыта раньше установки расширения, восстановлена из кэша (back/forward), открыта в другом
профиле браузера или расширению урезали доступ к сайту («При клике» вместо «На всех сайтах»).
Перезагрузка страницы помогает не всегда, поэтому попап умеет подключаться сам:

- кнопка **«Подключить к вкладке»** — `chrome.scripting.executeScript` внедряет те же четыре
  файла, что и манифест (`vendor/parser.js`, `core.cjs`, `dom.cjs`, `content.js`), и попап
  сразу переспрашивает их;
- **«Самопроверка»** на шаге 2 делает то же самое автоматически и пишет, чем кончилось;
- повторное внедрение безопасно: контент-скрипт оставляет на `window` метку экземпляра и,
  увидев живой, просто выходит — второго таймера и второй отправки не будет. Если расширение
  обновили и старый экземпляр умер (`Extension context invalidated`), новый снимает его таймер
  и запускается вместо него;
- для этого в манифесте нужно разрешение `scripting` (оно там есть, версия 1.0.1). Если вы
  обновили папку расширения, нажмите в `chrome://extensions` кнопку **«Обновить»** (↻) —
  без неё Chrome держит старый манифест, и кнопки «Подключить к вкладке» не будет.

## Проверка, что всё работает

```bash
# 1. сервер жив и приём включён (enabled: true)
curl https://pop-utka.app/api/ingest/status

# 2. контракт целиком, без записи в БД (dryRun)
curl -X POST https://pop-utka.app/api/ingest \
  -H "Authorization: Bearer $INGEST_TOKEN" -H 'Content-Type: application/json' \
  -d '{"collector":"tg-web-ext/1.0.0","dryRun":true,"messages":[
        {"chatId":"web:test","messageId":1,
         "text":"25.09 Варшава — Брест, возьму посылку до 20 кг, +48 579 264 254"}]}'

# 3. что видит клиент в вашей вкладке
#    попап → «Самопроверка» (8 шагов: вкладка, контент-скрипт, сервер, токен, белый список, приём)
#    попап → «Диагностика вкладки»  или  панель → «Диагностика» (текст копируется в буфер)

# 4. панель видит аккаунт и настройки (ADMIN_API_TOKEN)
curl -H "Authorization: Bearer $ADMIN_API_TOKEN" https://pop-utka.app/api/admin/extension
curl -H "Authorization: Bearer $ADMIN_API_TOKEN" \
  "https://pop-utka.app/api/admin/ingest/log?limit=20"
```

На сервере результат виден в `GET /api/admin/collect/status` (`listingsByOrigin.extension`)
и в админке на вкладке «чат» (этап 6).

## Ошибки и что они значат

| Что в панели | Причина | Действие |
|---|---|---|
| `Токен не принят (401)` | неверный/отозванный `INGEST_TOKEN` | перепроверить токен; сбор остановлен до исправления |
| `Приём выключен на сервере (503)` | на воркере не задан `INGEST_TOKEN` | `wrangler secret put INGEST_TOKEN` |
| `Сервер ответил 429. Подождём N с` | часовой лимит запросов на токен | ничего не делаем: клиент сам повторит после окна лимита |
| `Сервер ответил 5xx` | воркер перезапускается/лежит | экспоненциальный backoff, повтор автоматически |
| `Сервер отклонил запрос (400/413)` | клиент шлёт не то, что ждёт контракт | баг клиента: смотрите `extension/core.cjs → buildPayload` |
| `Нет связи с сервером` | сеть/CORS/домен не в `host_permissions`; для юзерскрипта — ещё и mixed content (http-адрес с https-страницы) | добавить домен в `manifest.json` (локальные `http://127.0.0.1/*`, `http://localhost/*` и `https://*.e2b.app/*` уже внесены), проверить CORS на сервере |
| `⚠ Не могу прочитать сообщения` | Telegram Web изменил разметку (или чат пуст) | править списки селекторов в `extension/dom.cjs` |
| `Вкладка не отвечает…` в попапе | вкладка открыта до установки расширения, восстановлена из кэша, открыта в другом профиле, либо расширению урезали доступ к сайту | попап → **«Подключить к вкладке»**: скрипт внедрится сам, без перезагрузки. Не вышло — «Самопроверка» покажет причину; проверьте `chrome://extensions` → «Ошибки» и «Доступ к сайту» → «На всех сайтах» |
| `Белый список пуст` | не задано ни одной записи (локально и в панели) | заполнить в попапе или в панели: «Аккаунт Telegram (расширение)» → белый список |
| `рум не совпал` | запись `чат :: тема` задана на другой рум, чем открыт | открыть нужный рум или убрать `::` из записи |

Счётчик `errors` в попапе растёт именно на нечитаемой разметке — это сигнал, что сбор
встал, а не «просто нет новых сообщений».

## Разметка изменилась: как чинить

Все селекторы — списки кандидатов в начале `extension/dom.cjs`
(`MESSAGE_CONTAINERS`, `TEXT_SELECTORS`, `AUTHOR_SELECTORS`, `DATE_SELECTORS`,
`ID_ATTRS`, `CHAT_TITLE_SELECTORS`, `CHAT_USERNAME_SELECTORS`). Порядок:

1. В вкладке Telegram Web: DevTools → найти узел одного сообщения → скопировать его
   класс/атрибуты.
2. Добавить вариант в соответствующий список (список перебирается сверху вниз, первым
   непустым результатом и пользуется).
3. `messageId` берётся из атрибутов `ID_ATTRS`, иначе из ссылки `t.me/<chat>/<id>`,
   иначе синтезируется устойчивый id (`core.syntheticMessageId`) — серверная
   дедупликация по `(chatId, messageId)` при этом продолжает работать. Если клиент
   отдаёт составной id (`peerId_msgId`), берётся **последняя** группа цифр; коллизии
   внутри прохода автоматически превращаются в синтетические id.
4. Прогнать тесты: `npx vitest run tests/extension-dom.test.ts tests/extension-content.test.ts`
   (разметка моделируется в `tests/helpers/fake-dom.ts` — добавьте туда новый вариант дерева).

## Безопасность и границы

- Клиент **не пишет** в аккаунт Telegram: не кликает, не отправляет, не ставит реакции,
  не пересылает, не скроллит ленту и не подгружает историю.
- Читаются только чаты из белого списка; всё остальное игнорируется до чтения DOM.
- Собранные объявления всегда попадают в очередь модерации (`pending`), `AUTO_APPROVE`
  на них не действует.
- Автоматизация клиентского аккаунта — на ваш страх и риск: используйте отдельный номер,
  держите интервал ≥ 120 с и включённый `confirmMode`.

## Файлы

| Файл | Роль |
|---|---|
| `entry-parser.ts` | точка входа бандла: какие функции `src/parser.ts` нужны клиенту |
| `vendor/parser.js` | собранный esbuild бандл парсера (`globalThis.PoputkaParser`) — клиентский детект |
| `core.cjs` | чистая логика: настройки, белый список, ключи чата, детект, дедупликация, батчи, backoff, контракт `/api/ingest` |
| `dom.cjs` | чтение DOM: селекторы-кандидаты, id/даты/авторы, `harvest`, «не могу прочитать» |
| `content.js` | оркестратор: таймер, проход, отправка, панель, обмен с попапом |
| `popup.html` / `popup.js` | настройки, счётчики, «Проверить сервер», «Диагностика вкладки» |
| `manifest.json` | MV3: `storage`, content scripts на `web.telegram.org`, `host_permissions` — прод-домен, `*.workers.dev`, локальные `127.0.0.1`/`localhost` и `*.e2b.app` |

`core.cjs` и `dom.cjs` — UMD с расширением `.cjs` намеренно: в MV3 content scripts
грузятся обычным `<script>` (ES-модули там недоступны), а в тестах тот же файл
подключается через `createRequire` — логика одна и проверяется без браузера
(`tests/extension-core.test.ts`, `tests/extension-dom.test.ts`, `tests/extension-content.test.ts`).

## Перенос в Bergaff/parcel

Папка `extension/` (и `userscript/`) копируется в репозиторий `parcel` **как есть** —
это не код воркера, в сборку Worker она не входит. Серверная сторона приёма
(`POST /api/ingest`, миграция `0006_ingest.sql`, квоты ИИ) описана в `INTEGRATION.md`
в корне этого репозитория.
