# Клиентская часть: расширение и юзерскрипт для Telegram Web

Этап 3 ТЗ (`parcel/docs/tz-auto-collection.md`, вариант B). Работает в **уже открытой
вкладке** `web.telegram.org` на аккаунте заказчика и **только читает DOM**: никакой
отправки сообщений, реакций и пересылок. Найденные объявления уходят на сервер
в `POST /api/ingest` и там попадают в очередь модерации (`status = pending`).

Единственное исключение из «не трогаем вкладку» — **автообход чатов** (по умолчанию
выключен): он переключает открытый чат/рум, чтобы не листать их руками. Подробнее и
с честным предупреждением о риске — в разделе «Автообход чатов и румов».

Две одинаковые по поведению поставки из одних и тех же файлов:

| Что | Куда ставить | Файлы |
|---|---|---|
| Расширение Chrome (MV3) | `chrome://extensions` → «Загрузить распакованное расширение» → папка `extension/` | `manifest.json`, `popup.html`, `popup.js`, `content.js`, `core.js`, `dom.js`, `vendor/parser.js` |
| Юзерскрипт (Tampermonkey/Violentmonkey) | открыть `userscript/poputchka-collector.user.js` → «Установить» | один файл, собирается из тех же исходников |

## Что делает проход

```
таймер (60–600 с, по умолчанию 120)
  → какой чат и рум открыты? (dom.readChatInfo: заголовок, @username из хэша, peer-id и id рума из URL)
  → чат (и рум, если он указан) в белом списке?  нет → сообщения НЕ ЧИТАЮТСЯ вовсе
  → чтение последних N сообщений ленты (dom.harvest, N = maxPerChat, по умолчанию 30)
  → клиентский детект на бандле src/parser.ts: пассажирские, болтовня, сервисные — в корзину
     (вердикт по КАЖДОМУ сообщению — в журнал «Что нашлось»: 🟢 объявление / ⚪ отсеяно + причина)
  → не старше maxAgeHours (72) и ещё не отправлялось (локальный лог chatId:messageId)
  → confirmMode? да → список в панели, ждём клик «Отправить найденные»
  → батчи по batchSize (≤ 20) → POST /api/ingest, Authorization: Bearer <INGEST_TOKEN>
  → счётчики (найдено/отправлено/создано/дубли/отсеяно) + лог отправленного в storage
```

Панель с состоянием, кнопками «Отправить найденные», «Пауза», «Диагностика» и
«Настройки» — в правом нижнем углу вкладки.

Читается **только открытый сейчас чат** (и только открытый рум, если он указан в белом
списке): без автообхода расширение не перебирает чаты само — хотите другой чат или рум,
откройте его в Telegram, следующий проход пойдёт по нему. С включённым автообходом
([раздел ниже](#автообход-чатов-и-румов)) чаты из белого списка открываются сами, по кругу
и со случайными паузами.

### Что нашлось: журнал разбора и ссылки на сообщения

Каждое прочитанное сообщение попадает в журнал (последние 60, новые сверху) — в панели
вкладки, в попапе и в тексте «Диагностики»:

| Что видно | Пример |
|---|---|
| вердикт | `🟢 объявление`, `⚪ отсеяно`, `🔁 уже отправляли`, `🕑 старое` |
| причина по-русски | «нет признаков объявления (обычная переписка)», «про поездку людей, без посылок», «нет контакта для связи» |
| автор и текст | `Сергей: 25.09 Варшава — Брест, возьму посылку до 20 кг…` |
| **ссылка на сообщение** | `t.me/travelersminsk/91529/713464` — кликабельна, открывается в Telegram |
| отметка об отправке | `✅ отправлено на сервер` |

Ссылка строится как это делает сам Telegram: публичный чат — `t.me/<чат>[/<рум>]/<сообщение>`,
приватная супергруппа — `t.me/c/<id>[/<рум>]/<сообщение>` (открывается у участников). По ней
сообщение открывают и пересылать приходится вручную — расширение ничего не публикует.
Если DOM-клиент не отдал настоящий id сообщения (id синтезирован для дедупликации), ссылки
не будет: журнал честно пишет «ссылки нет», а не подсовывает битую. У обычной группы и личного
чата ссылок на сообщение в Telegram не существует вовсе.

## Автообход чатов и румов

Когда целей много (румы `travelersminsk`, `belgranica`, `granica_es`, `granica_bypl`,
дальше — другие направления), переключать чаты руками и ждать прохода невозможно.
Автообход делает это сам: расширение открывает чаты и румы из белого списка по кругу,
читает их и идёт дальше.

```
план = белый список (порядок сохранён, повторы схлопнуты)
  → сколько проходов прочитали в этом чате?  меньше walkReadsPerChat → читаем ещё раз
  → дочитали → случайная пауза walkMinSec…walkMaxSec (по умолчанию 60–240 с)
  → пауза кончилась → НЕ переключаем, если:
       · вы сами печатаете/кликаете во вкладке (walkIdleGuardSec тишины, 45 с);
       · переходов за час уже walkMaxPerHour (20) — ждём минуту и пробуем снова;
       · стоит «Пауза» или обход выключен
  → переход: адресом вкладки (#travelersminsk/91529 в Web K, #/im?p=@granica_es в Web A),
    а если клиент адрес не понял или цель задана названием — кликом по строке в списке чатов
  → ждём, пока чат дорисуется (до 15 с): открылся → читаем; не открылся → запись в журнале,
    возврат прежнего адреса и переход к следующей цели (провалившуюся не долбим до конца круга)
  → круг замкнулся → снова первая цель; уже отправленные сообщения НЕ уходят повторно
```

### Как включить

| Где | Как |
|---|---|
| Попап расширения | галочка **«Автообход чатов»** + поля темпа (проходов на чат, пауза от/до, переходов в час, «не мешать») → «Сохранить» |
| Панель в вкладке Telegram | кнопка **«Обход: включить»** / «Обход: выключить» (справа внизу). Там же видно: сейчас / дальше / переход через N с / переходов за час / журнал переходов |
| Панель сервера | админка → вкладка «чаты» → «Аккаунт Telegram (расширение)» → «автообход» и темп → «сохранить и передать расширению». Клиент заберёт настройки следующим проходом |

По умолчанию автообход **выключен**: это осознанный шаг, а не поведение «из коробки».

### Настройки обхода

| Поле | По умолчанию | Смысл |
|---|---|---|
| `autoWalk` | `false` | включать ли обход вовсе |
| `walkReadsPerChat` | `2` | сколько проходов чтения сделать в чате, прежде чем идти дальше (1–20) |
| `walkMinSec` / `walkMaxSec` | `60` / `240` | границы случайной паузы между переходами, с (минимум 10 с) |
| `walkMaxPerHour` | `20` | предел переходов в час: больше — обход ждёт (1–600) |
| `walkIdleGuardSec` | `45` | сколько секунд вашей активности во вкладке считать «человек работает» и не переключать чат (0 — не учитывать) |

Границы одинаковы в клиенте (`extension/core.js → withDefaults`) и на сервере
(`src/store.ts → normalizeExtensionConfig`): панель не может задать темп, который клиент
счёл бы безумным.

### Что видно в журнале обхода

Каждый переход пишется в журнал (последние 25, в панели и в попапе — 8/12 последних):

| Запись | Смысл |
|---|---|
| `→ переход granica_es` · «перехожу (по адресу)» | обход сменил адрес вкладки |
| `✔ открыт travelersminsk/91529` | чат/рум дорисовался, читаем |
| `✔ открыт …(id рума клиент не отдал — беру из белого списка)` | клиент не показал id рума, он взят из ссылки в белом списке |
| `✖ не открылся belgranica/174591` · «не открылся за 15 с — пропускаю» | нет доступа к чату, клиент не понял адрес или страница зависла: цель пропущена до конца круга |
| `→ переход …` · «адрес не сработал — пробую кликом по «…»» | запасной путь: клик по строке в списке чатов |

### Границы и риск — честно

- Обход **только открывает чаты и читает**. Он ничего не отправляет, не публикует, не
  ставит реакции, не печатает текст и не пересылает сообщения от вашего имени.
- Это всё равно **автоматизация клиентского аккаунта**, а ТЗ её не предусматривало
  (п. 4.5 — «только чтение открытой вкладки»). Формально такие действия могут
  рассматриваться Telegram как автоматизация пользовательского аккаунта, и теоретически
  способны привести к предупреждению или ограничению аккаунта. Риск небольшой (темп
  человеческий: паузы 60–240 с, ≤ 20 переходов в час, 2 прохода на чат, никаких записей),
  но он **не нулевой**.
- Поэтому: держите обход на **отдельном аккаунте с дешёвой SIM-картой**, состоящем в этих
  же публичных супергруппах, — тогда круглосуточный сбор не связан с вашим основным
  номером и перепиской. На основном аккаунте обход лучше не включать вовсе.
- Остановить можно мгновенно: «Пауза» (обход и чтение), «Обход: выключить», закрытие
  вкладки. Пока вы сами работаете во вкладке, обход чат не вырывает.
- Состояние обхода (индекс цели, переходы за час, журнал) переживает перезагрузку вкладки:
  обход не начинает круг заново и не «бодрит» Telegram лишними переходами.

## Установка расширения

Пошагово «с нуля до первой заявки», включая локальный сервер одним кликом
(`start-local.bat` / `./start-local.sh`) — в [`docs/try-it.md`](../docs/try-it.md).

1. Соберите бандл парсера (нужен один раз, файл `vendor/parser.js` уже лежит в репозитории):
   ```bash
   npm install
   npm run build:ext
   ```
2. `chrome://extensions` → включите «Режим разработчика» → «Загрузить распакованное
   расширение» → выберите папку `extension/`.
3. Откройте `https://web.telegram.org/k/` (или `/a/`), войдите в аккаунт заказчика и
   зайдите в чат из белого списка.
4. Кликните иконку расширения и заполните настройки (см. ниже) → «Сохранить».

## Установка юзерскрипта

1. `npm run build:ext` → `userscript/poputchka-collector.user.js`.
2. В Tampermonkey/Violentmonkey: «Создать новый скрипт» → вставить содержимое файла
   (или открыть файл в браузере — менеджер предложит установку).
3. Настройки юзерскрипта живут в `localStorage["poputchka"]` (попапа у него нет).
   В консоли вкладки Telegram Web:
   ```js
   localStorage.setItem('poputchka', JSON.stringify({ settings: {
     serverUrl: 'https://pop-utka.app',
     token: 'ВАШ_INGEST_TOKEN',
     // рум (топик) форум-чата — ссылкой из Telegram или записью с '::'; без указания рума читаются все румы
     whitelist: ['https://t.me/travelersminsk/91529', 't.me/granica_es',
                 'Водители Польша–Беларусь', 'Граница :: Очередь BY-PL'],
     intervalSec: 120, batchSize: 20, maxPerChat: 30,
     confirmMode: true, paused: false, maxAgeHours: 72, requireContact: false,
   }}));
   location.reload();
   ```

## Настройки

| Поле | По умолчанию | Смысл |
|---|---|---|
| `serverUrl` | — | базовый URL сервера, например `https://pop-utka.app` (без `/api`). Для локальной отладки годится `http://127.0.0.1:8790` или `http://localhost:8790` — прочие `http://` адреса попап не примет: страница Telegram Web открыта по https, и браузер заблокирует запрос как mixed content |
| `token` | — | `INGEST_TOKEN` с сервера: `wrangler secret put INGEST_TOKEN` |
| `whitelist` | `[]` | чаты и румы, которые вообще разрешено читать (форматы записей — таблица ниже). **Пусто — ничего не читается** |
| `intervalSec` | `120` | период опроса, жёстко ограничен 60–600 с |
| `batchSize` | `20` | сообщений в одном `POST` (серверный предел — 100) |
| `maxPerChat` | `30` | сколько последних сообщений ленты читать за проход |
| `maxAgeHours` | `72` | старее — не отправляем (сервер дополнительно режет по `INGEST_MAX_AGE_DAYS`) |
| `confirmMode` | `true` | спрашивать подтверждение перед отправкой |
| `requireContact` | `false` | слать только сообщения с телефоном или `@username` |
| `paused` | `false` | пауза: ничего не читать и не отправлять |
| `autoWalk` | `false` | автообход: самому открывать чаты и румы из `whitelist` по кругу (см. раздел выше) |
| `walkReadsPerChat` | `2` | проходов чтения на один чат, прежде чем перейти дальше |
| `walkMinSec` / `walkMaxSec` | `60` / `240` | границы случайной паузы между переходами, с |
| `walkMaxPerHour` | `20` | предел переходов в час |
| `walkIdleGuardSec` | `45` | пока вы активны во вкладке — чат не переключаем (секунд тишины) |

### Форматы записей белого списка

| Запись | Что читает |
|---|---|
| `https://t.me/travelersminsk/91529` | один рум (топик) форум-чата — **ссылку можно копировать прямо из Telegram** |
| `https://t.me/travelersminsk/91529/713464` | тот же рум: это ссылка на сообщение в нём, первое число — рум, второе — сообщение |
| `t.me/travelersminsk` или `@travelersminsk` | весь чат со всеми румами |
| `Travelers Minsk` | чат по названию (как оно видно в шапке Telegram Web) |
| `Граница :: Очередь BY-PL` или `Граница :: 7` | рум по названию или по id — старый способ, работает как раньше |
| `https://t.me/c/1234567890` | приватная супергруппа/канал по внутреннему id (весь чат) |
| `https://t.me/c/1234567890/91529` | один рум приватного форум-чата |

Тонкости:

- В форум-чате запись с румом **строгая**: открыт другой рум или список тем — сообщения не
  читаются, панель пишет «рум не совпал» или «рум не прочитался».
- Двухчастная ссылка (`t.me/<чат>/<число>`) неоднозначна: это может быть и рум, и ссылка на
  сообщение обычного чата. Если открытый чат не похож на форум, такая запись смягчается до
  «весь чат», чтобы сбор не встал молча. В форум-чате она остаётся строгой.
- Если клиент не отдал id рума в адресе вкладки, а в белом списке за этим чатом закреплён ровно
  один рум, расширение берёт id оттуда и **предупреждает** в панели: «id рума взят из ссылки в
  белом списке (клиент не отдал его в адресе). Проверьте, что открыт рум «…»».
- Белый список из панели сервера перекрывает локальный (синтаксис тот же).

Токен хранится только в `chrome.storage.local` / `localStorage` этого браузера и в
репозиторий не попадает.

## Панель как пульт: «аккаунт Telegram», румы, журнал

Авторизация Telegram остаётся здесь, в браузере: расширение читает DOM открытой вкладки,
никакого логина по номеру телефона на сервере нет (юзербот — это риск бана аккаунта и
прямой запрет ТЗ п. 1.3). Панель сервера при этом работает пультом этого единственного
авторизованного аккаунта.

Что происходит между ними:

| Кто | Что | Как |
|---|---|---|
| расширение → панель | «аккаунт подключён»: текущий чат и рум, счётчики, состояние, ошибки | `POST /api/extension/heartbeat` каждый проход (и в ответе сразу приходят настройки) |
| панель → расширение | белый список чатов и румов, интервал опроса, пауза | `GET /api/extension/config` в начале каждого прохода |
| модератор в панели | журнал принятого: чем стало сообщение и **ссылка на него** | `GET /api/admin/ingest/log` |

Практические следствия:

- Настройки из попапа остаются запасными: как только панель задала белый список, он
  **перекрывает** локальный (в попапе это видно строкой «настройки из панели»).
- Чтобы забрать настройки немедленно, а не в следующий проход: попап → «Настройки из панели».
- Ссылки в журнале: публичный чат — `t.me/<username>[/<рум>]/<id>`, приватная супергруппа —
  служебная `t.me/c/<id>[/<рум>]/<msg>` (открывается у участников чата). Рум попадает в ссылку,
  потому что расширение присылает `topicId` (миграция `0007_source_topic.sql`). Её и пересылают
  вручную: расширение ничего не публикует и не пересылает от вашего имени. Тот же журнал со
  ссылками виден в панели вкладки и в попапе — блок «Что нашлось».
- Если в адресе вкладки peer-id нет (например, личный чат без `p=`/`#-100…`), ссылки на
  сообщение не существует — журнал честно пишет «ссылки нет», а не подсовывает битую.
- Вкладка закрыта или браузер выключен — через ~12 минут панель покажет «нет связи».
  Это нормально: сбор продолжится, когда вкладку снова откроют.

## Если попап не видит вкладку: «Подключить к вкладке»

Chrome внедряет контент-скрипт при загрузке страницы. Внедрения не будет, если вкладка
открыта раньше установки расширения, восстановлена из кэша (back/forward), открыта в другом
профиле браузера или расширению урезали доступ к сайту («При клике» вместо «На всех сайтах»).
Перезагрузка страницы помогает не всегда, поэтому попап умеет подключаться сам:

- кнопка **«Подключить к вкладке»** — `chrome.scripting.executeScript` внедряет те же четыре
  файла, что и манифест (`vendor/parser.js`, `core.js`, `dom.js`, `content.js`), и попап
  сразу переспрашивает их;
- **«Самопроверка»** на шаге 2 делает то же самое автоматически и пишет, чем кончилось;
- повторное внедрение безопасно: контент-скрипт оставляет на `window` метку экземпляра и,
  увидев живой, просто выходит — второго таймера и второй отправки не будет. Если расширение
  обновили и старый экземпляр умер (`Extension context invalidated`), новый снимает его таймер
  и запускается вместо него;
- для этого в манифесте нужно разрешение `scripting` (оно там есть, версия 1.0.1). Если вы
  обновили папку расширения, нажмите в `chrome://extensions` кнопку **«Обновить»** (↻) —
  без неё Chrome держит старый манифест, и кнопки «Подключить к вкладке» не будет.

## Проверка, что всё работает

```bash
# 1. сервер жив и приём включён (enabled: true)
curl https://pop-utka.app/api/ingest/status

# 2. контракт целиком, без записи в БД (dryRun)
curl -X POST https://pop-utka.app/api/ingest \
  -H "Authorization: Bearer $INGEST_TOKEN" -H 'Content-Type: application/json' \
  -d '{"collector":"tg-web-ext/1.0.0","dryRun":true,"messages":[
        {"chatId":"web:test","messageId":1,
         "text":"25.09 Варшава — Брест, возьму посылку до 20 кг, +48 579 264 254"}]}'

# 3. что видит клиент в вашей вкладке
#    попап → «Самопроверка» (8 шагов: вкладка, контент-скрипт, сервер, токен, белый список, приём)
#    попап → «Диагностика вкладки»  или  панель → «Диагностика» (текст копируется в буфер)

# 4. панель видит аккаунт и настройки (ADMIN_API_TOKEN)
curl -H "Authorization: Bearer $ADMIN_API_TOKEN" https://pop-utka.app/api/admin/extension
```

На сервере результат виден в `GET /api/admin/collect/status` (`listingsByOrigin.extension`)

## Ошибки и что они значат

| Что в панели | Причина | Действие |
|---|---|---|
| `Токен не принят (401)` | неверный/отозванный `INGEST_TOKEN` | перепроверить токен; сбор остановлен до исправления |
| `Приём выключен на сервере (503)` | на воркере не задан `INGEST_TOKEN` | `wrangler secret put INGEST_TOKEN` |
| `Сервер ответил 429. Подождём N с` | часовой лимит запросов на токен | ничего не делаем: клиент сам повторит после окна лимита |
| `Сервер ответил 5xx` | воркер перезапускается/лежит | экспоненциальный backoff, повтор автоматически |
| `Сервер отклонил запрос (400/413)` | клиент шлёт не то, что ждёт контракт | баг клиента: смотрите `extension/core.js → buildPayload` |
| `Нет связи с сервером` | сеть/CORS/домен не в `host_permissions`; для юзерскрипта — ещё и mixed content (http-адрес с https-страницы) | добавить домен в `manifest.json` (локальные `http://127.0.0.1/*`, `http://localhost/*` и `https://*.e2b.app/*` уже внесены), проверить CORS на сервере |
| `⚠ Не могу прочитать сообщения` | Telegram Web изменил разметку (или чат пуст) | править списки селекторов в `extension/dom.js` |
| `Вкладка не отвечает…` в попапе | вкладка открыта до установки расширения, восстановлена из кэша, открыта в другом профиле, либо расширению урезали доступ к сайту | попап → **«Подключить к вкладке»**: скрипт внедрится сам, без перезагрузки. Не вышло — «Самопроверка» покажет причину; проверьте `chrome://extensions` → «Ошибки» и «Доступ к сайту» → «На всех сайтах» |
| `Белый список пуст` | не задано ни одной записи (локально и в панели) | заполнить в попапе или в панели: «Аккаунт Telegram (расширение)» → белый список |
| `рум не совпал` | запись `чат :: тема` задана на другой рум, чем открыт | открыть нужный рум или убрать `::` из записи |
| `Белый список пуст — обходить нечего` | автообход включён, а целей в белом списке нет | заполнить белый список (ссылками из Telegram — см. форматы ниже) |
| `«…» не открылся за 15 с — пропускаю` | нет доступа к чату, клиент не понял адрес (например, рум в Web A) или страница зависла | проверить, что аккаунт состоит в этом чате; для Web A задать рум названием (`чат :: тема`) — обход пойдёт кликом |
| `Вы сами работаете во вкладке — чат не переключаю ещё N с` | сработал «не мешать» (`walkIdleGuardSec`) | ничего не делать: обход продолжится сам, когда вы перестанете печатать/кликать |
| `Предел переходов в час (N) достигнут — обход подождёт` | упираемся в `walkMaxPerHour` | поднять предел, если темп кажется вам безопасным, или оставить как есть |
| `Не смог открыть «…»: нет ни адреса, ни строки «…» в списке чатов` | цель задана названием, а в боковой панели её сейчас нет (архив, другой аккаунт) | открыть чат руками один раз или задать цель ссылкой `t.me/<чат>` |

Счётчик `errors` в попапе растёт именно на нечитаемой разметке — это сигнал, что сбор
встал, а не «просто нет новых сообщений».

## Разметка изменилась: как чинить

Все селекторы — списки кандидатов в начале `extension/dom.js`
(`MESSAGE_CONTAINERS`, `TEXT_SELECTORS`, `AUTHOR_SELECTORS`, `DATE_SELECTORS`,
`ID_ATTRS`, `CHAT_TITLE_SELECTORS`, `CHAT_USERNAME_SELECTORS`). Порядок:

1. В вкладке Telegram Web: DevTools → найти узел одного сообщения → скопировать его
   класс/атрибуты.
2. Добавить вариант в соответствующий список (список перебирается сверху вниз, первым
   непустым результатом и пользуется).
3. `messageId` берётся из атрибутов `ID_ATTRS`, иначе из ссылки `t.me/<chat>/<id>`,
   иначе синтезируется устойчивый id (`core.syntheticMessageId`) — серверная
   дедупликация по `(chatId, messageId)` при этом продолжает работать. Если клиент
   отдаёт составной id (`peerId_msgId`), берётся **последняя** группа цифр; коллизии
   внутри прохода автоматически превращаются в синтетические id.
4. Прогнать тесты: `npx vitest run tests/extension-dom.test.ts tests/extension-content.test.ts`
   (разметка моделируется в `tests/helpers/fake-dom.ts` — добавьте туда новый вариант дерева).

## Безопасность и границы

- Клиент **не пишет** в аккаунт Telegram: не отправляет сообщения, не ставит реакции,
  не пересылает, не печатает текст, не скроллит ленту и не подгружает историю.
- Читаются только чаты из белого списка; всё остальное игнорируется до чтения DOM.
- Собранные объявления всегда попадают в очередь модерации (`pending`), `AUTO_APPROVE`
  на них не действует.
- **Автообход** — единственное действие во вкладке: он меняет адрес открытого чата
  (как если бы вы вставили ссылку) и, если адрес не сработал, один раз кликает по строке
  чата в боковой панели. Он выключен по умолчанию, ограничен по темпу (пауза 60–240 с,
  ≤ 20 переходов в час, «не мешать» 45 с) и останавливается мгновенно.
- Автоматизация клиентского аккаунта — на ваш страх и риск: используйте **отдельный номер**
  (дешёвая SIM, состоящая в тех же публичных чатах), держите интервал ≥ 120 с и включённый
  `confirmMode`. С обходом на основном аккаунте риск ограничения мал, но не нулевой.

## Файлы

| Файл | Роль |
|---|---|
| `entry-parser.ts` | точка входа бандла: какие функции `src/parser.ts` нужны клиенту |
| `vendor/parser.js` | собранный esbuild бандл парсера (`globalThis.PoputkaParser`) — клиентский детект |
| `core.js` | чистая логика: настройки, белый список, ключи чата, детект, дедупликация, батчи, backoff, контракт `/api/ingest` |
| `dom.js` | чтение DOM: селекторы-кандидаты, id/даты/авторы, `harvest`, «не могу прочитать» |
| `content.js` | оркестратор: таймер, проход, отправка, панель, обмен с попапом |
| `popup.html` / `popup.js` | настройки, счётчики, «Проверить сервер», «Диагностика вкладки» |
| `manifest.json` | MV3: `storage`, content scripts на `web.telegram.org`, `host_permissions` — прод-домен, `*.workers.dev`, локальные `127.0.0.1`/`localhost` и `*.e2b.app` |

`core.js` и `dom.js` — UMD: в MV3 content scripts грузятся обычным `<script>`
(ES-модули там недоступны), а в тестах тот же файл подключается через `createRequire` —
логика одна и проверяется без браузера (`tests/extension-core.test.ts`,
`tests/extension-dom.test.ts`, `tests/extension-content.test.ts`).

**Расширение `.js` обязательно.** Chrome определяет тип файла контент-скрипта по расширению,
и на `.cjs` отвечает ошибкой в `chrome://extensions` → «Ошибки»:

> Invalid script mime type: Не удалось загрузить файл core.cjs для скрипта обработки контента.

Из-за неё не внедряется **весь** список файлов, поэтому попап пишет «контент-скрипт не
подключён», сколько ни обновляй страницу. До версии 1.0.2 файлы назывались `core.cjs`/`dom.cjs` —
если у вас старая копия папки, обновите её (`git pull`) и нажмите «Обновить» (↻) в
`chrome://extensions`. Чтобы Node при этом всё так же считал эти файлы CommonJS
(в корневом `package.json` стоит `"type": "module"`), рядом лежит `extension/package.json`
с `"type": "commonjs"` — Chrome на него не смотрит.

## Перенос в Bergaff/parcel

Папка `extension/` (и `userscript/`) копируется в репозиторий `parcel` **как есть** —
это не код воркера, в сборку Worker она не входит. Серверная сторона приёма
(`POST /api/ingest`, миграция `0006_ingest.sql`, квоты ИИ) описана в `INTEGRATION.md`
в корне этого репозитория.
